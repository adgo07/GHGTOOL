## 3. 明确采用、差异与真实状态

按已批准C01，行业声明引用方式、实际采用的通则版本／修订、固定规则组或规则ID、差异目标、专属字段、明确不适用和未决项。采用清单作为行业 JSON 的一部分，不新增庞大清单系统。

规则组必须展开为固定成员及依赖。不能使用随上游增项自动扩围的“最新全部”。每个行业仍核对边界、气体、总量、来源、因子资格和报告要求，但不重复制作共同定义。

复用现有 `SPECIALIZE / OVERRIDE / EXTEND / SUPPLEMENT / CONFLICT_REVIEW`；覆盖指向明确目标和属性，不能靠提高 priority 或后加载覆盖先加载代替依据。来源集合不自动取并集。

| 状态 | 含义与处理 |
|---|---|
| 已采用且适用 | 根据上下文执行 |
| 已采用、当前条件不满足 | 当前不触发，不丢失采用关系 |
| 行业明确不适用 | 有条款／映射依据，排除并保留理由 |
| 企业本次不涉及 | 企业活动状态，不改变标准适用范围 |
| 标准要求但软件未支持 | 能力缺口，不得伪称不适用；受影响核算不能宣称完整 |
| 未配置／未核验／真实冲突 | 不猜、不隐式放行；定位受影响规则和功能 |

当前行业合法覆盖的待审项可以保留追踪，不因此阻断无关业务；未处理且影响当前正式结果的冲突不得被忽略。不适用不是消除错误提示的快捷按钮。

## 4. 空值与缺省：先在加载边界确定机器含义

### 4.1 三种层次分别检查

**原始差异层：** 合法省略“未改变的属性”不等于配置错误，但必须存在明确、固定的被采用定义；不允许靠找不到字段来猜继承。

**完整有效定义层：** 对该字段类型必需的属性，组装后仍缺失就是配置错误。可选的说明文字不必强制填满。名称、方向等不需要来源属性的字段，也应能明确表达该属性不适用。

**业务输入层：** 输入框为空是用户尚未填写，不是规则文件缺失；是否阻断由适用性、必填及当前阶段判断。三层不能混用。

### 4.2 明确表示状态，不使用空值暗号

| 状态 | 机器含义 |
|---|---|
| 必需定义属性缺失 | 加载／组装校验失败，定位字段及文件，不作为正式规则使用 |
| 明确不适用 | 有结构化状态和理由，不通过空数组暗示 |
| 适用全部已采用上下文 | 显式声明，范围仍受行业采用清单限制，不等于所有行业 |
| 当前无合法来源 | 明确不可形成有效输入并给出原因；空集合不是任意来源 |
| 不需要来源选择 | 字段类型不使用该属性，例如名称或流向 |
| 来源固定一种 | 保留来源语义；是否显示标签另由渠道呈现决定 |
| 没有自动默认 | 合法的明确状态，不等于默认缺省值，也不等于定义缺失 |
| 尚未确定／条件待满足 | 暂不取默认、不假装已具备绑定资格 |

具体 JSON 键名由执行者采用一种严格结构实现，不必为本方案逐个键审批。关键是 missing、null、空数组和空字符串不能兼任多个状态。

`RuleApplicability` 旧接口空集合的含义不做盲目全局替换。严格加载器先识别上述状态；只有显式“全部已采用上下文”才能受控转换为旧引擎的无过滤表示，缺失与无合法选项不得转过去。

JSON Schema 需显式声明必需属性并校验类型；仅列出 properties 并不会自动要求属性出现，null 也不等于缺失。[R14] 未知字段、重复ID、重复键、未知策略、悬空引用及循环依赖应被发现，不能容忍错别字静默失效。

## 5. 一项属性只有一个求值责任

| 属性形式 | 谁提供最终值 | 其他层不得做什么 |
|---|---|---|
| 固定名称、单位、来源集合等 | Canonical 定义 | Python／控件另写同义字典或来源列表 |
| 条件属性 | 定义指定的唯一登记策略求值 | JSON一份判断、策略另一份判断、页面再过滤一遍 |
| 参数候选和值 | 行业资格＋现有 Resolver 的真实绑定 | 用非空source_id、相似名称或首项候选冒充资格 |
| 业务操作后的状态 | 统一非Qt输入服务 | 控件刷新函数顺手初始化、改源或改单位 |
| 实际显示 | 读取已求值视图的渠道适配器 | 为简洁自行改专业名称或扩大选项 |
| 正式校验 | 同一业务规则与真实输入／参数资格 | 信任UI传来的“已校验”标记 |

源配置对同一属性只能选固定值或策略引用之一；需要基础值与条件变更时，在同一个明确策略中组合，避免不明确的双重权威。

策略可以在报告导出、模板生产、审阅展开和正式校验中复用，但报告读取历史记录时采用与记录相容的解释版本，不调用当前默认策略改变冻结结果。

条件审阅不得只显示函数名。必须展开可审核的条件分支、最终允许来源、默认、读写状态与依据。例如：单组分且有通用绑定时允许缺省／实测并默认缺省；多组分只允许实测、不自动复制90%。连续条件用范围和边界说明，不穷举无限数值。

每条影响正式结果的规则要能定位实际校验或计算消费者、字段及案例。只用于说明、来源追踪或人工业务责任的条目明确标注；不强迫所有原则变成算法，也不把登记视为约束已实现。

复用现有同类资产，不机械新建副本；字段、条件和策略采用稳定ID。完整有效规则、审阅表及运行资源是生成结果，不成为第二可编辑生产源。

JSON不含任意表达式、eval、脚本路径或远程执行。复杂公式、插值和操作处理继续由版本化Python实现。迁移后的 `default_g05_rules()` 可以保留兼容读取入口，但其旧活动定义退出。

本轮不引入二进制浮点容差，也不改变现有正式数值规则。涉及业务数值的十进制常量、阈值、比例和修约参数按现有Numeric要求处理，推荐以规范十进制字符串交给已有Decimal策略；不得先经二进制float再转Decimal。确需接受JSON数值时明确Decimal解析，拒绝NaN和Infinity，布尔值不冒充业务数值。[R15]

整数计数、布局尺寸等与业务十进制值分开；不借此重构全项目数值策略。因子生产值仍在目录，UI和模板仅消费或生成受控快照；显示修约不得回流正式计算。

规则修订按业务含义变化记录；颜色、间距和纯换行不要求每次提升业务规则版本。渠道文案／模板内容变化记录对应资源修订及hash；来源、单位含义、默认和资格变化属于业务变更，不能伪称纯样式。

| 新建 | 仅在新建初始化适用默认；无绑定不伪造缺省 |
| 名称编辑 | 保留草稿，不提前改变确认身份，不重置参数 |
| 确认名称 | 规范名或已登记唯一别名匹配后处理依赖；模糊搜索不直接确立身份 |
| 切换来源 | 保存／恢复对应来源的草稿，不把默认数值改标签冒充实测或计算 |
| 换单位／计量路径 | 同量纲换算与质量↔体积等数量含义变化分开；无依据不只换标签 |
| 增删组分 | 按本设施／脱硫剂实例计数；单转多不复制90%，多转单不覆盖已确认值 |
| 恢复项目 | 先忠实还原，按第10节决定计算与升级，不当作新建补默认 |
| 刷新／折叠／导航 | 不修改业务输入、来源和采用版本 |
| Excel导入 | 批量转换、共同求值／校验；不模拟鼠标，不默认覆盖已填值 |
| 正式核算 | 重新检查规则版本、对象、数量、单位、来源及实际绑定；致命错误不产生Record |

草稿至少按稳定实例、对象身份、字段、条件／路径和来源隔离；不按行号、下拉索引保存身份。同初态与操作产生同业务结果，首行／第二行不能采用不同规则。

目录属性到业务来源的转换统一到非UI边界，按字段实际语义处理；不让SYSTEM_CONSTANT在GUI变成PROJECT_SPECIFIED、Excel变成CALCULATED而无明确依据。官方发布、标准规定等证据分类与三类业务来源分开，不能为统一文案一律改标为计算值。

has_resolver_binding必须由真实核验产生；默认参数缺失时明确提示，不能在控件或恢复中用常量补值。来源说明可空仅提醒的现有决定保持，不增加强制上传检测报告等门槛。


### 7.1 名称确认、重置与草稿恢复的明确边界

| 操作 | 统一服务行为 |
|---|---|
| 燃料A真正切换为燃料B | 按B的真实绑定重新确定默认来源、参数和计量方式；无合法绑定不借用A的缺省 |
| 同一已确认身份再次选中、失去焦点或刷新候选 | 不作为对象切换，不覆盖已确认实测输入 |
| 目录燃料改为自定义燃料 | 清除失效绑定，原目录缺省不得继续冒充自定义参数；自行填写参数并按合法来源核验 |
| 名称尚在编辑 | 保留文本草稿，不将模糊搜索结果确立为身份，不提前重置 |
| 项目恢复、Excel导入 | 恢复已保存的输入与真实身份，不执行新选择对象的初始化 |
| 明确离开某燃料后重新选择它 | 按对象选择规则重新确定默认；保存过该燃料草稿不意味着自动恢复草稿 |

同一身份的重复控件事件与用户真正切换对象必须分开。所有行使用同一服务，首行和新增行采用相同规则；针对二者执行同操作样例。来源草稿按第7节隔离，不能通过恢复草稿抵消重新选择燃料的默认规则。碳酸盐复用身份确认原则，参数及单／多组分默认仍由其专属规则决定。

## 8. 软件、Excel模板和Word的同源一致性

### 8.1 同一业务定义，不是把界面截图复制成文件

所有渠道共用受控字段身份、概念、单位语义、来源资格、默认条件、采用依据和必要解释。一般渠道名称默认一致；确需按标准表头或批准简称显示不同文字时，在同一字段定义下登记渠道投影、依据和适用范围，而非各写一套。

同源一致的比较对象必须注明：标准组合／规则版本、字段与条件、渠道、Record（如有）。新版本模板不要求与十年前记录的全部文字机械一致；旧报告不得被当前定义静默改写。

| 内容 | GUI | Excel 输入模板 | Word／记录业务表 |
|---|---|---|---|
| 字段名称与单位 | 统一字段视图，单位持续可见 | 表头和子表头映射同字段，允许标准规定的合并表达 | 同一报告模型／字段投影，不另造术语 |
| 允许来源 | 消费当前字段条件的合法集合 | 相同条件尽量等价的数据验证、锁定和清晰说明 | 显示真实采用来源和所需证据，不生成新选择 |
| 默认与只读 | 统一操作服务＋真实参数绑定 | 能由已知上下文确定才预置；不能仅因空白模板就猜默认 | 冻结采用值，无实时Resolver重新取默认 |
| 候选、地区、年度 | 按适用绑定查询 | 携带时属于明确目录版本的受控快照 | 按Record保存的身份、年度和采用值 |
| 说明、脚注与警告 | 采用同一业务依据 | 不留与软件相冲突的旧脚注和操作说明 | 正文、附注和表格不得改写解释或漏掉必需说明 |
| 状态 | 未填／不适用／无资格等明确区分 | 明确填写和导入规则 | 不把未记录／不适用／真实零值混成0 |

“GUI隐藏固定碳／挥发分下方实测值标签”仅隐藏冗余控件，不授权删掉标准表要求的数据来源栏，也不抹去Word的来源事实。反之，Word表式有一列来源，不代表GUI每个字段下必须重复摆标签。

电力框后显示年份、CO₂下标、因子精度同样约束实际导出；必要量纲换算必须明确，不将ratio直接当百分数，也不在某一渠道擅自按两位小数显示所有小因子。

### 8.2 Excel模板：受控生产，下载不重绘，导入不信任验证框

保留已有 `ExcelTemplateService` 和已批准附录B母版结构。将“受控语义内容维护”与“最终下载”分开：

```text
有效业务定义＋允许的渠道投影＋版本化目录切片
→ 模板字段／数据验证／脚注的受控生成或同步
→ 对照标准表式及独立预期检查实际XLSX
→ 形成经批准的模板修订，登记版本／hash／兼容关系
→ 软件按字节复制该资源
→ 用户填写后导入，按识别版本解码并走共同业务校验
```

能程序生成的受控文字和验证从定义生成；因母版限制必须保留静态内容时，将其作为受控产物，并用字段绑定及独立预期验证，不让它成为可单独决定业务的主源。不重新绘制九表，不静默覆盖Owner原始母版。

模板中的燃料候选、隐藏配置表、命名区域、数据验证公式、固定参数、提示、批注和脚注均纳入检查。数据验证若用公式或引用区域，检查展开后的实际语义，不只比较公式字符串。

条件可以被工作簿表达时，显示合法的条件化选项；若无宏模板不能完整复制GUI状态机，不能以此要求引入VBA／联网工具，也不能宣称完全相同的交互。永久禁止的来源不得重新列入；复杂条件明确提示并在导入／正式服务严格核验。不能借“Excel做不到”在导入端扩大资格。

Excel数据验证可能被复制／填充等方式绕过，这是正式导入校验不可省略的原因。[R16] 验证绕过案例应能定位工作表、单元格、字段及问题，不生成正式Record。

填过的工作簿当然不再具有空白母版hash。空白下载要求字节一致；用户文件要求合法版本识别、结构与业务语义通过，不要求其hash等于母版。旧模板按明确兼容表读取；未知版本不靠猜测套最新模板。

这项工作涉及的是当前提供的Excel输入模板，不重新引入此前取消的“核算结果Excel导出”，也不新增Excel独立核算算法。已有必要单位／显示辅助公式不能替代正式计算器。


**公式单元格：** 明确允许填写数据的单元格接收公式的策略，优先沿用已有批准规则。不得把未经可靠确认的公式缓存当作正式输入，不得把缺失缓存当零。当前不支持公式输入时，应定位工作表和单元格，提示用户粘贴数值；不新建Excel计算引擎。模板自身的受控辅助公式与企业输入公式分别处理。实际回导样例覆盖公式、缺失／陈旧缓存等受现有策略影响的情况，不能只测试常量。

### 8.3 Word与软件记录详情：继续共用报告模型

沿用 `build_report_model / build_saved_record_report → ReportModel → Qt业务表、Word renderer`。标准专属报告投影负责把冻结输入和输出映射到标准表式；渲染器负责排版，不再决定专业含义。

现有 `appendix_b_layout.json` 的布局、合并、宽度与分页可以保留；标题、表头、来源短名和脚注等受控内容必须改为统一定义的生成投影或有明确依据的版本化模板内容，不能保留独立业务词典。

报告采用所选Record及其相容解释版本。不得读取当前编辑中的草稿或实时目录替换冻结值；不得因为历史没有记录某个派生项就在报告中重新算出一个伪装历史值。合法显示单位转换与显示修约属于呈现，需与记录／规则一致且不改变正式结果。

数据来源类别与证据定位分开表达。不能让“表C.1”取代必须显示的来源类别，也不能为了删“填写值”把历史未知来源改成实测。标准要求的可见证据放在可导出的内容中，不能仅存在于GUI悬浮提示；可选审计信息保持可追溯，不额外制造资料必填门槛。

同一Record的界面业务表与Word应比较表标题、字段、单位、值、来源、年度、必要脚注及缺失状态。换行、分页、列宽不要求相同；专业意义不能不同。


**普通报告附注：** 使用业务对象和字段名称定位，不使用“第1行第3列”等内部坐标。来源栏显示批准的简短类别；必要依据、适用条件和影响理解的警告放在表下。完整审计信息保留在记录中，不默认逐项倾倒到报告。表内已有且无需解释的信息不在附注重复。报告投影明确哪些说明必需，渲染器不得自行拼接专业说明。历史未知来源不得为了简洁改成实测或计算。

### 8.4 检查实际产物，而不是只检查配置或对象相等

现有sections等价测试保留；再用少量高风险独立样例检查实际文件：

- **XLSX：** 读取生成模板的真实表头、数值格式、命名区域、数据验证及脚注；填入合法／非法数据并回导；按已采用组合检查来源、单位、默认和参数身份。
- **DOCX：** 渲染后读取真实正文、表格和必要元数据，确认未遗漏或改名；必要少量页面检查下标、裁切和分页，不以截图代替语义检查。
- **跨入口：** 同一业务输入从GUI与Excel形成等价Canonical输入和结果；从相应Record生成Word，比较相同字段及证据，不只比较总排放量。

测试期望不能全部从被测生产定义自生。独立标准／批准决定样例用于防止“大家同源但一起错”；产物检查用于防止“模型正确但最终文件漏掉或写错”。

## 10. 项目打开、继续计算和规则升级

### 10.1 分开三种兼容能力

支持表分别说明：**可读取输入、可继续计算、可解释／导出历史Record。** 可以读取并不保证还能执行；历史报告可导出并不意味着当前安装包含旧计算器；不承诺永久支持全部历史计算。

仅有标准年份不够，还要定位采用组合、规则修订、必要编解码器和计算器版本。旧项目没有可唯一定位的信息时显示“规则版本未确认”，不能凭文件日期、名称或当前默认猜认版本。

### 10.2 打开与继续计算

```text
打开项目 → 忠实恢复输入和已记录版本，不写回升级
         → 检查明确执行支持表和采用组合
         → 可执行：显示所用版本，以该组合校验后计算
         → 不可执行／未知：可查看和提取输入，提供升级入口，不静默按最新计算
```

“可执行”还要求没有被明确撤销的来源资格或政策。不能通过选旧规则重新放行已被Owner禁止的新核算兜底来源；读取旧USER_DEFINED记录只表示证据可读，不等于旧政策获准继续新计算。

### 10.3 升级操作

升级先生成只读影响摘要：旧／新版本、字段资格、来源、单位、默认、候选及潜在重新确认项。未重算前不编造结果差异；需要试算时明确是预览，不写正式Record。

用户确认后，优先通过现有本地项目复制或既有修订快照保留原输入；不用新增可移植.qzproj格式。升级后的项目通过结构、版本和转换完整性校验后，可保存为待完善项目。缺失数据、来源待确认等业务问题明确保留并阻止正式核算，但不阻止草稿保存。技术转换失败不得覆盖原项目；取消不写回，技术失败不留下半升级项目。数据安全保存与正式核算资格分别校验。

不把旧值静默改成新缺省、不把旧来源改标为实测、不把原单位活动量解释为另一路径。可确定的技术转换仍需被明确记录；待确认项保留原始值及证据。

升级本身不生成正式Record。用户再明确计算并成功后新增Record；任何旧Record及其关联证据不覆盖。重新计算按钮须显示采用组合，不暗中意味着全部采用最新规则。

从旧项目下载输入模板时，选择与项目采用组合相容的受控版本；没有相容模板就说明需要升级或改用可支持流程，不悄悄下载一个改变口径的最新模板。普通首页“下载模板”可继续指向当前正式版本并标明版本。

## 11. 审阅工作簿：覆盖条件与操作，不只一字段一行

默认只维护一个生成审阅工作簿，至少两张主表和一张自动差异表：

| 工作表 | 内容 |
|---|---|
| 字段与条件规则 | 字段ID、条件ID、含义、各渠道名称／单位、合法来源、默认来源和绑定依据、数值锁定、来源锁定、可见性、依据、消费者与案例、未决项 |

## 12. 发布组合一致性与安装包检查

### 12.1 复用现有build-manifest，不再建平行发布系统

发布组合至少可定位：应用提交／构建、行业与通则规则修订、采用组展开身份、软件政策、策略及编解码器、计算器／Numeric Profile、目录数据版本、Excel模板版本与hash、报告布局／投影版本。

**兼容组合不要求所有版本号和hash相同。** 输入模板2.2.0、报告布局3.0.1等可以合法组合，但必须有验证过的对应关系；只要“都叫V1”或文件hash正确，不足以证明语义相容。

声明允许的组合或最小明确兼容关系，避免任意范围自动放行。发布审计既检查完整性，也检查必要角色之间的兼容；新增规则不只登记在源码文档中。

### 12.2 Canonical源与部署资源分开

现有发布禁止data-source及未登记资源。[R11] 因此将选定的已核验定义生成可部署、只读的运行资源，例如精确登记的`resources/business_rules/`产物；名称由实施确定，不能加载相对开发目录。

记录源Canonical身份、生成器／schema、运行资源hash及所属采用组合；如果资源中包含规则副本，它是可复现的派生产物，禁止人工改成第二主源。继续使用catalog.sqlite作为已有目录部署格式，不为本任务强制新增数据库结构。

构建与检查器从明确清单取得新增资源，保持禁止开发资料、原标准全文、用户数据和无关文件。不得简单允许整个data-source或resources目录绕过审计。

### 12.3 校验时机与失败行为

打包时验证完整组合；启动或首次加载该标准时检查资源身份和相容性；正式计算校验已加载组合与项目采用组合一致，不在每个导航和每个字段上重复计算全部文件hash。

模板下载复用字节校验；Word导出确认记录投影与渲染器相容。发现不相容只阻止受影响的核算／模板／报告功能，说明具体缺项；不使用旧缓存、空规则或硬编码默认继续执行。无关历史查看和安全功能不无故阻断。

安装包专项必须在没有源码目录的环境中，从真实打包资源完成：启动、下载模板、回导代表输入、计算、查看记录业务表、导出Word、读取关键产物内容。复用现有交付脚本，不新增多层门禁。

## 13. 多标准UI与导航性能

公共Shell、首页、导航、字段／来源／因子组件和导出操作不直接依赖`.34`、B.2、C.1或八张卡片。行业通过现有注册提供分组、字段、策略、绑定和必要编辑器／模板／报告适配。

允许专属组件，不承诺所有新行业UI零改动。同名字段不自动共用资格；缓存关联采用版本、对象、路径、地区、口径、期间和目录版本。少量测试专用差异标准验证隔离，不对外冒充第二正式行业。

导航N专项独立计时：首页／侧栏、首次／再次、无数据变更／新增记录后、代表性记录规模；区分点击反馈、构造、查询、布局、首次有效绘制和真正可操作。

优先消除无变化全量读取、重复建页、多轮布局及每次导航解析全部规则。按数据变化失效，不能漏掉另一入口／仓储实例新增记录。规则在采用组合变化时加载，字段条件变化只更新必要依赖。

加载动画不替代优化；不通过关闭校验、丢弃草稿、滤掉数据或循环处理事件掩盖阻塞。验收同机同数据对比，记录慢路径及较慢分位，不把固定毫秒值作跨硬件保证。

### 14.2 B中两种提交必须区分

**纯迁移：** 旧／新预期相同，比较语义状态、Canonical输入、单位、来源、身份、冻结证据和结果，必要展示归一化后比较，不比较随机Record ID或生成时间。

**已批准修正：** 记录旧行为、新行为、批准依据和独立预期。旧实现不是兼容真值，不能为“等价”保留已确认错误；也不能把修正混进迁移，再通过放松测试解释差异。

**历史代码退出条件：**
