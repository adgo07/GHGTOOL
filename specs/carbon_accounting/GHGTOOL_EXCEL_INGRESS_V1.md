# GHGTOOL Excel 数值入口 V1

状态：RS03-A 本地入口策略；不是中央 Frozen Contract，也不宣称 GB/T 32151.34—2024 已获完整支持。

适用模板：`GB_T_32151_34_2024_EXCEL_SCHEMA_V1.md`。实现：`packages/excel/gbt32151_34_v1.py`。策略标识：`GHGTOOL_EXCEL_INGRESS_V1`。

## 1. 入口原则

Excel 是适配器。它只负责读取工作簿、保留入口证据、校验结构并构造标准业务输入；业务校验和计算继续使用现有 `CarbonMaterialInput` 与 `CarbonMaterialCalculator`。该适配器是纯 Python，不依赖 Qt，不保存 Project，也不生成或修改正式 Record。

本策略规定 GHGTOOL 当前 Windows 工作簿入口接受什么数据，不冻结跨产品 Excel / OOXML Decimal 互操作规范。中央 Decimal ingress 词法语义仍为 OPEN；本仓不得把本地策略描述为中央合同。

## 2. 工作簿身份与来源

模板由运行时生成，不将 `.xlsx` 模板资产提交或打包。每个工作簿对应一个标准，可登记多个彼此独立的核算单元。隐藏 `__metadata__` 页记录模板 ID / 版本、标准 ID / 版本和入口策略 ID；导入预览另记录：

- 原始工作簿 SHA-256；
- 模板 ID 与版本；
- 标准 ID 与版本；
- 入口策略 ID；
- UTC 导入时间。

每个被读取的数值单元格形成入口证据，至少包括工作表、单元格位置、Excel 单元格类型、工作簿库读值表示、OOXML 保存数值文本及解析后的 `Decimal`。OOXML 数值文本代表**文件保存的数值词法**，不代表用户编辑器里最初键入的字符；Excel 保存时可能规范化用户键入形式，事后无法恢复未保存在文件中的字符。

## 3. 数值单元格规则

正式数值字段只接受有限的 Excel 数值单元格。入口以 `data_only=False` 读取工作簿，并从工作表 XML 读取对应数值文本后直接构造 `Decimal`，不经 Python 二进制浮点数转换计算值。

- 只接受数值单元格类型及其保存的数值文本；文本数字、公式、日期/时间、布尔值和缺失数值序列化均拒绝。
- 公式单元格一律拒绝，不读取公式缓存值，不执行或信任公式。
- `NaN`、`Infinity`、`-Infinity` 和其他非有限 Decimal 一律拒绝。
- 最多接受 15 位有效数字。超出时按该核算单元报错，不舍入、不截断、不自动修复。
- 合法的 0 保留为 0；空白只按字段本身的必填/可选语义处理，不推导为 0。
- 科学计数法按保存的数值文本解析；它不会绕过有效数字上限。
- 比例字段按实际数值 `0..1` 解释。Excel 百分比格式只影响显示，不作为转换依据；保存值 `0.98` 表示 98%，保存值 `98` 不会因 `number_format` 自动改成 `0.98`。
- 单元格样式、显示格式和显示精度不能替代保存数值，也不能为输入提供标准含义。

因此，例如 `1.23456789012345` 可通过 15 位上限，`1.234567890123456` 会被拒绝；把单元格格式设为百分比不会改变底层值的解释。

## 4. 校验范围和错误隔离

工作簿结构、元数据版本或必需工作表不可识别时，整个工作簿校验失败。模板只要求四个可见工作表：`填写说明`、`核算单元`、`燃料与能源`、`过程排放`，以及一个隐藏的 `__metadata__` 工作表。可识别工作簿中的错误按核算单元隔离：错误单元不执行成功计算，其他有效单元仍可单独校验和预览。停用单元、无法关联的业务行和未知自定义页签不参与计算，并形成可复核提醒。

排放源状态从业务数据派生：存在该类业务行即为涉及，没有业务行即为不涉及。启用单元中出现不完整、无效或格式错误的行时，该单元失败，不会把错误输入当作“未涉及”。活动数据或实测参数来源随业务明细行填写，预览证据可回链到工作簿 SHA-256 与表格位置；不使用单独的证据登记页。

错误定位使用工作表和单元格，普通 UI 展示中文可操作信息，不展示内部校验码、Rule ID 或 Mapping ID。任何致命错误不得形成成功的单元预览或正式记录。

## 5. 核算单元隔离与计算

企业名称、核算期间和公共边界信息在工作簿级填写；核算单元清单维护每个单元的名称、“全厂 / 工序 / 其他”类型、启用状态与边界说明。各明细行按核算单元名称关联。每个单元分别构造 `CarbonMaterialInput`，有效输入交给现有标准 Calculator。

不同核算单元不自动合并、不分摊、不交叉引用输入，也不形成项目级总计。一个单元失败不会污染另一个有效单元。预览显示燃料、生产过程、烟气治理、购入电力/热力、输出电力/热力分项，以及直接、净间接和总排放。预览阶段不写入 Project、Workspace 或 Record 存储；RS03-B 才负责正式导入和既有 Project / Record 生命周期接通。
